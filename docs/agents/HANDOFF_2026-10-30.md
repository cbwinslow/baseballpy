## Done today

- **All five source reviews are finished and archived**: Chadwick and Lahman (earlier), Retrosheet, Statcast, MLB API (`openspec/changes/archive/2026-10-30-*`). Also archived: `dlt-processed-tier-spike`, `verify-optin-paths`, `reference-docs`, `data-workflow-standard`.

- **New shared mechanisms:** schema digest in every stored chunk (ADR 49), dataset `revision` for parser fixes (ADR 51), `response_fingerprint` for sources with no version marker, `table(name, season)` Python entry points for Statcast and MLB, registry-name `--datasets` for MLB, the `documents` job for Statcast, audit logging on every Retrosheet and Statcast operation.
- **The 406:** `GET /api/v1/stats` answers 406 for every query, user agent and header (provider fault). League-wide season pools now fall back to `/v1/people?hydrate=stats(...)` (ADR 53). `baseballpy probe` checks every provider route in about 3 seconds: **run it before any long ingest.** No 403 was reproducible; our user agent is pybaseball's (`python-requests/2.32.3`).
- **Real-data checks found and fixed** (each has a test that fails without the fix): non-unique keys (Retrosheet rosters, substitutions, box starters, box batting; MLB nine datasets), empty strings vs NULL (Retrosheet events, MLB), dictionary-column read-back (Statcast Parquet/CSV export), list columns (DuckDB/PostgreSQL export), a refused request aborting a whole MLB season run, hard-coded default season 2024 in MLB.
- **Export with read-back verification** passed for Parquet, CSV, DuckDB and PostgreSQL on Retrosheet (2015-2026), Statcast (2025) and MLB (2025).

## Not verified / known shortcomings (be honest about these)

1. **A whole MLB default season (`ingest mlb_api -s 2025`) was not rerun in one piece after the fixes.** It takes about 50 minutes (990-team fan-out for rosters, coaches, personnel, alumni). The parts were rerun separately. Run `baseballpy probe` first, then the full run once, on the homelab if disk is short.
2. **League-wide pools for the minor-league sports through the fallback** were not run (one sport at a time needs about 115 player-batch requests for the big levels). Sport 1 (MLB): 34 pools in 144 s, 8 projected pools in 13 s.
3. **All-time pools without a season** (`career*`, `statsSingleSeason*`, 15 pools) have no player list to batch over and stay blocked by the 406. Retest the route at most once an hour (`mlb-stats-route-406-and-deep-pools` task 1.2, B-32); the paging fix for the three 190k-row pools (5xx at deep offsets) is unit-tested only.
4. **Schema drift from the fallback:** hydrate splits carry `gameType` and `numLeagues`, which the direct-route schemas lack. They are kept in `_extras` (no data lost) and logged as `schema_drift` per request (noisy). Regenerate those pool schemas through the fallback (generator `--only`, never the full run) to type them.
5. **Four pools are empty for 2025 / sport 1:** `stats_season_advanced_fielding`, `..._advanced_catching`, `..._advanced_game`, `stats_sabermetrics_fielding`. The per-person route was also empty for the one player checked, so this is probably real, but it was not checked for several players or seasons.
6. **Non-unique registered keys that are provider facts** (documented in the dataset descriptions; export with replace or append, not merge): MLB `transactions_season`, `stats_leaders`, `team_coaches`, `team_roster_coach`, `team_personnel`, `jobs_datacasters`, `jobs_official_scorers`, `team_roster_gameday` (one repeat). A coach with two jersey numbers cannot be told apart because an empty jersey number is NULL.
7. **Column descriptions:** Retrosheet 1,012 of 1,280 (79%): all event, daily, substitution and game-log columns cited from Chadwick's documents (pinned commits); box accounts, derived box scores, rosters, schedules, umpires, discrepancies and the reference CSVs need retrosheet.org documents, which are unreachable (curl timeout, connection refused, Wayback 429). Statcast 293 of 977 (30%): leaderboard columns have no published definitions found. MLB 56%. Nothing was invented. Open: B-14, B-15, B-16, B-18, B-19 (owner or external).
8. **2026 data:** upstream has only `2026SCHEDULE.CSV` for Retrosheet (games arrive after the World Series; moving the pinned ref in `core/sources_lock.json` brings them, no code change). Statcast 2026 was not ingested (not verified); the planner takes any season from the calendar.
9. **Parser-only fixes are not detected by the schema digest** unless the dataset `revision` is raised (ADR 49, 51). Remember to bump the revision whenever a parser change alters stored values.
10. **Statcast `FIRST_SEASON = 2008` / `FIRST_MINORS_SEASON = 2021` in `statcast/adapter.py`** are provider facts hard-coded as constants; they should come from a probe or the registry (small follow-up, not tracked as a task).
11. **`PostgreSQL` export of very wide datasets** (Retrosheet events, 164 columns, 2 million rows) took 270 s and 1.3 GB of memory on this PC; larger seasons may need streaming (`write_stream`).
12. **Quarantine singleton writes to the default home** instead of the lake in use (Retrosheet review finding R-F18, deferred).
13. `scripts/gen_mlb_schemas.py` still depends on the lake for team lists when run with `--only` on endpoints that fan out (use `BASEBALLPY_HOME=<a lake with teams_season>`).
