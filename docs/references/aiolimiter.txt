### AsyncLimiter.__init__(max_rate, time_period=60)

Source: https://github.com/mjpieters/aiolimiter/blob/main/_autodocs/api-reference/async-limiter.md

Initializes an AsyncLimiter instance with the given maximum rate and time period. The limiter allows up to max_rate acquisitions per time_period seconds, and starts empty so the first burst passes immediately.

```APIDOC
## AsyncLimiter.__init__(max_rate, time_period=60)

### Description
Initializes an AsyncLimiter instance with the given maximum rate and time period. The limiter allows up to max_rate acquisitions per time_period seconds, and starts empty so the first burst passes immediately.

### Signature
```python
def __init__(self, max_rate: float, time_period: float = 60) -> None:
```

### Parameters
| Parameter | Type | Required | Default | Description |
|-----------|------|----------|---------|-------------|
| `max_rate` | `float` | yes | — | Allow up to `max_rate` / `time_period` acquisitions before blocking. Also the maximum burst size and the maximum capacity requestable in a single `acquire()` call. |
| `time_period` | `float` | no | `60` | Duration, in seconds, of the time period in which to limit the rate. |

### Return
`None`. The constructor initialises internal state: `_rate_per_sec = max_rate / time_period`, `_level = 0.0`, `_last_check = 0.0`, `_waker_handle = None`, and an empty waiter heap.

### Behaviour notes
- The limiter starts empty, so the first up-to-`max_rate` acquisitions pass immediately (a burst); the limit only kicks in once `max_rate` capacity has been consumed (see `has_capacity`/`acquire`).
- To forbid bursts, set `max_rate` to `1` and `time_period` to the minimum interval between acquisitions, e.g. `AsyncLimiter(1, 1.5)` allows entry every 1.5 seconds (pattern shown in `docs/index.rst`).
- No validation is performed on the constructor arguments; e.g. a zero or negative `time_period` is accepted by `__init__` (the resulting `_rate_per_sec` would simply be `0` or negative) — this is not checked statically, only `acquire()`'s `amount` argument is validated (see [acquire](#acquire-amount1) and [errors.md](../errors.md)).

### Example — basic use
```python
import asyncio
from aiolimiter import AsyncLimiter

async def main() -> None:
    # at most 100 acquisitions per 60 seconds (the default window)
    limiter = AsyncLimiter(100)
    # at most 5 acquisitions per 10 seconds
    strict = AsyncLimiter(5, 10)

asyncio.run(main())
```

### Example — burst-suppressing configuration
```python
import asyncio
from aiolimiter import AsyncLimiter

async def main() -> None:
    # no bursts: the section can be entered at most once per 1.5 seconds
    limiter = AsyncLimiter(1, 1.5)  # max_rate == 1
    async with limiter:
        ...  # exclusive, rate-limited section

asyncio.run(main())
```

import asyncio

### AsyncLimiter class declaration and usage example

Source: https://github.com/mjpieters/aiolimiter/blob/main/_autodocs/api-reference/async-limiter.md

The AsyncLimiter class implements a leaky bucket rate limiter. It is designed to be used as an asynchronous context manager to control the rate of operations within an event loop.

```python
class AsyncLimiter(AbstractAsyncContextManager[None]):
    """A leaky bucket rate limiter.

    This is an :ref:`asynchronous context manager <async-context-managers>`;
    when used with :keyword:`async with`, entering the context acquires
    capacity::

        limiter = AsyncLimiter(10)
        for foo in bar:
            async with limiter:
                # process foo elements at 10 items per minute

    :param max_rate: Allow up to `max_rate` / `time_period` acquisitions before
       blocking.
    :param time_period: duration, in seconds, of the time period in which to
       limit the rate. Note that up to `max_rate` acquisitions are allowed
       within this time period in a burst.

    """
```

from aiolimiter import AsyncLimiter

limiter = AsyncLimiter(5, 10)

if limiter.has_capacity(0.5):

### AsyncLimiter error handling and weighted amounts

Source: https://github.com/mjpieters/aiolimiter/blob/main/_autodocs/api-reference/async-limiter.md

Shows how to handle ValueError exceptions when acquiring capacity and how to request specific weighted amounts.

```python
import math
from aiolimiter import AsyncLimiter

async def worker() -> None:
    limiter = AsyncLimiter(100, 60)

    # a "heavy" request that should count as 10 units of capacity
    try:
        await limiter.acquire(10)
    except ValueError:
        # amount is out of range (e.g. 0.0 <= amount <= max_rate violated)
        # this also covers NaN and negative/infinite values
        raise

    # wait until 0.5 units of capacity are free, timed out by the caller
    if limiter.has_capacity(0.5):
        await limiter.acquire(0.5)
```

### Description

- **tb** (TracebackType | None) - Required - The traceback of the exception, if any.

### Returns
None

### Example

        raise RuntimeError("boom")

### Description
Creates a leaky bucket rate limiter. Up to `max_rate` acquisitions are permitted within a rolling `time_period` window, after which acquisition calls block until the bucket has leaked enough capacity.

### Import Path

- Not a thread-safe object; create one instance per event loop. Re-using an instance across loops triggers a `RuntimeWarning`.

Acquires capacity in the limiter. If the limit has been reached, blocks until enough capacity has been freed before returning. Raises ValueError if amount is not a number between zero and max_rate, inclusive.

```APIDOC
## acquire(amount=1)

### Description
Acquires capacity in the limiter. If the limit has been reached, blocks until enough capacity has been freed before returning.

### Method
async def acquire(self, amount: float = 1) -> None

### Parameters
- **amount** (float) - Optional, default: 1 - How much capacity you need to be available. Must satisfy 0 <= amount <= max_rate.

### Return
None - the coroutine returns only once the requested capacity has actually been acquired.

### Throws
- **ValueError** - if amount is not between 0 and max_rate inclusive (negative values, NaN, -inf, +inf, or values greater than max_rate).

### Behaviour notes
- If there is enough capacity, acquisition is immediate and _level is incremented by amount.
- Otherwise the caller pushes an entry onto the waiter heap and awaits its future; _wake_next() drains leaked capacity and wakes the head of the heap when enough time has elapsed.
- Mixing amounts: when at or near max_rate, small requests tend to be served before large blocks of capacity.

### Example - basic call
```python
import asyncio
from aiolimiter import AsyncLimiter

async def fetch(url: str) -> None:
    rate_limit = AsyncLimiter(10, 1)  # 10 requests per second
    await rate_limit.acquire()        # blocks until capacity is available
    # ... perform the network request
    await asyncio.sleep(0.1)

async def main() -> None:
    await asyncio.gather(*(fetch(f"https://example.com/{i}") for i in range(50)))
```

### Example - error handling and weighted amounts
```python
import math
from aiolimiter import AsyncLimiter

async def worker() -> None:
    limiter = AsyncLimiter(100, 60)

    # a "heavy" request that should count as 10 units of capacity
    try:
        await limiter.acquire(10)
    except ValueError:
        # amount is out of range (e.g. 0.0 <= amount <= max_rate violated)
        # this also covers NaN and negative/infinite values
        raise

    # wait until 0.5 units of capacity are free, timed out by the caller
    if limiter.has_capacity(0.5):

### has_capacity(amount=1)

Source: https://github.com/mjpieters/aiolimiter/blob/main/_autodocs/api-reference/async-limiter.md

Non-blocking, non-consuming check to see if there is enough capacity remaining in the limiter. It leaks the bucket and compares the current level plus amount against max_rate without adding to the level.

```APIDOC
## Method: has_capacity(amount=1)

### Description
Check if there is enough capacity remaining in the limiter. This is a non-blocking, non-consuming check: it leaks the bucket and compares self._level + amount <= self.max_rate without adding anything to the level.

### Signature
```python
def has_capacity(self, amount: float = 1) -> bool:
    """Check if there is enough capacity remaining in the limiter.

    :param amount: How much capacity you need to be available.

    """
```

### Parameters
- **amount** (float) - Optional, default: 1 - How much capacity you need to be available.

### Return
bool - True if acquiring amount right now would not block, False otherwise.

### Behaviour Notes
- Unlike acquire(), no ValueError validation is performed on amount; e.g. has_capacity(42) on a limiter with max_rate=1 simply returns False.
- The check advances the internal _last_check clock (via _leak()), so it can itself free capacity for subsequent calls.

### Example - basic call
```python
from aiolimiter import AsyncLimiter

limiter = AsyncLimiter(1)          # one acquisition per minute
if limiter.has_capacity():
    # capacity available now - the next acquire() will not block
    await limiter.acquire()
else:
    print("rate limit reached, reject the request")
```

### Example - fractional capacity and early rejection
```python
from aiolimiter import AsyncLimiter

limiter = AsyncLimiter(5, 10)

# count a request as "light" - only needs half a unit
if limiter.has_capacity(0.5):
    await limiter.acquire(0.5)

# reject a "heavy" request immediately rather than blocking on it
if not limiter.has_capacity(4):
    return 429  # style: reject under load
```

```APIDOC
## AsyncLimiter.acquire(amount)

### Description
Acquires permission to proceed, raising a ValueError if the requested amount is outside the valid range (0 to max_rate). This is the only explicit failure condition in aiolimiter.

### Method
async def acquire(amount)

### Parameters
- **amount** (number) - Required - The amount of capacity to acquire. Must satisfy 0 <= amount <= max_rate.

### Errors
#### ValueError
- **Trigger condition**: amount fails the comparison 0 <= amount <= max_rate.
- **Message**: "Amount must be a number between 0 and the maximum capacity"
- **Source location**: src/aiolimiter/leakybucket.py, lines 140-142 (inside acquire, defined line 129)

### Values that trigger the error
- Negative numbers (e.g., -1, -0.5)
- float("-inf")
- float("inf") when max_rate is finite
- float("nan") - NaN compares false against everything
- Any value strictly greater than max_rate (e.g., 42 on an AsyncLimiter(1))

### Non-triggering values
- 0 (zero-capacity acquisition returns immediately and consumes nothing)
- Fractional values (e.g., 0.5)

### How to catch
```python
import asyncio
from aiolimiter import AsyncLimiter

async def main() -> None:
    limiter = AsyncLimiter(100, 60)
    try:
        await limiter.acquire(101)   # > max_rate → ValueError
    except ValueError as exc:
        print("amount out of range:", exc)
        # 'Amount must be a number between 0 and the maximum capacity'

asyncio.run(main())
```

### Notes
- The ValueError is raised only after awaiting the coroutine, since acquire is an async def.
- AsyncLimiter.has_capacity(amount) performs no such validation; it simply evaluates the comparison and returns False for out-of-range amounts.
```
