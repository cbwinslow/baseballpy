### Example: Using PyprojectTomlConfigSettingsSource

Source: https://github.com/pydantic/pydantic-settings/blob/main/_autodocs/api-reference/file-config-sources.md

Demonstrates how to use PyprojectTomlConfigSettingsSource in a custom settings source. The example assumes a pyproject.toml with [tool.pydantic-settings] containing port = 9000, and prints the value 9000.

```python
# pyproject.toml
# [tool.pydantic-settings]
# port = 9000

from pydantic_settings import BaseSettings, PydanticBaseSettingsSource, PyprojectTomlConfigSettingsSource

class Settings(BaseSettings):
    port: int = 8000

    @classmethod
    def settings_customise_sources(cls, settings_cls, init_settings, env_settings,
                                   dotenv_settings, file_secret_settings):
        return init_settings, PyprojectTomlConfigSettingsSource(settings_cls)

print(Settings().port)  # 9000
```

### Example: Using AzureKeyVaultSettingsSource with DefaultAzureCredential

Source: https://github.com/pydantic/pydantic-settings/blob/main/_autodocs/api-reference/cloud-secret-sources.md

Example of integrating AzureKeyVaultSettingsSource into a BaseSettings subclass via settings_customise_sources. It reads the secret 'connection-string' from the vault when dash_to_underscore is True.

```python
from azure.identity import DefaultAzureCredential

from pydantic_settings import AzureKeyVaultSettingsSource, BaseSettings, PydanticBaseSettingsSource

class Settings(BaseSettings):
    connection_string: str

    @classmethod
    def settings_customise_sources(cls, settings_cls, init_settings, env_settings,
                                   dotenv_settings, file_secret_settings):
        return init_settings, AzureKeyVaultSettingsSource(
            settings_cls,
            url='https://my-vault.vault.azure.net/',
            credential=DefaultAzureCredential(),
            dash_to_underscore=True,  # reads secret 'connection-string'
        )
```

### Constructor example with _env_prefix and _env_ignore_empty

Source: https://github.com/pydantic/pydantic-settings/blob/main/_autodocs/api-reference/base-settings.md

Shows how to instantiate BaseSettings with per-instance init kwargs _env_prefix and _env_ignore_empty. The environment variable APP_NAME is read because _env_prefix is set to 'APP_', and _env_ignore_empty=True ignores empty env values. The example prints the settings values.

```python
import os

from pydantic_settings import BaseSettings

os.environ['APP_NAME'] = 'demo'

class Settings(BaseSettings):
    name: str  # read from APP_NAME (env_prefix)
    port: int = 8080

# _-kwargs override per-instance:
s = Settings(_env_prefix='APP_', _env_ignore_empty=True)
print(s.name, s.port)
```

### Usage example for CliApp.run_subcommand

Source: https://github.com/pydantic/pydantic-settings/blob/main/_autodocs/api-reference/cli-app.md

Complete example showing a parent model (Git) with a subcommand (Init) and a cli_cmd method that dispatches to the subcommand via CliApp.run_subcommand. Running CliApp.run(Git, cli_args=['init', 'dir']) prints 'git init "dir"'.

```python
from pydantic import BaseModel

from pydantic_settings import CliApp, CliPositionalArg, CliSubCommand

class Init(BaseModel):
    directory: CliPositionalArg[str]

    def cli_cmd(self) -> None:
        print(f'git init "{self.directory}"')

class Git(BaseModel):
    init: CliSubCommand[Init]

    def cli_cmd(self) -> None:
        CliApp.run_subcommand(self)  # dispatches to Init.cli_cmd

CliApp.run(Git, cli_args=['init', 'dir'])  # prints: git init "dir"

```

### CliApp.serialize usage example

Source: https://github.com/pydantic/pydantic-settings/blob/main/_autodocs/api-reference/cli-app.md

Example showing how to serialize a model instance with default settings and with list_style='argparse' and positionals_first=True. The output demonstrates the resulting argument lists.

```python
from pydantic import BaseModel, Field

from pydantic_settings import CliApp

class Sub(BaseModel):
    that: dict

class App(BaseModel):
    this: list[str] = ['hello', 'world']
    nested: Sub = Sub(that={'a': 1, 'b': 2})
    arg: str = 'arg'  # positional-style single value

model = App(this=['hello', 'world'], nested=Sub(that={'a': 1, 'b': 2}), arg='arg')
print(CliApp.serialize(model))
# ['--this', '["hello", "world"]', '--nested.that', '{"a": 1, "b": 2}', 'arg']
print(CliApp.serialize(model, list_style='argparse', positionals_first=True))
# ['arg', '--this', 'hello', '--this', 'world', '--nested.that', '{"a": 1, "b": 2}']
```

### env_prefix_target examples for top-level fields

Source: https://github.com/pydantic/pydantic-settings/blob/main/docs/index.md

Shows four settings classes demonstrating the default behavior (variable only), 'all', 'alias', and 'variable' for env_prefix_target. The default behavior ignores env_prefix for aliases, reading from the unprefixed alias environment variable. The 'alias' example reads the alias with prefix but the variable without prefix.

```python
import os

from pydantic import Field

from pydantic_settings import BaseSettings, SettingsConfigDict


class FooBarSettings(BaseSettings):
    # default
    model_config = SettingsConfigDict(env_prefix='TARGET_')
    foo: str = Field(alias='FooAlias')
    bar: str


os.environ['FooAlias'] = 'TARGET_FOO_VALUE'  # (1)!
os.environ['TARGET_BAR'] = 'TARGET_BAR_VALUE'
print(FooBarSettings().model_dump())
#> {'foo': 'TARGET_FOO_VALUE', 'bar': 'TARGET_BAR_VALUE'}


class TargetAllSettings(FooBarSettings):
    model_config = SettingsConfigDict(
        env_prefix='TARGET_ALL_',
        env_prefix_target='all',
    )


os.environ['TARGET_ALL_FooAlias'] = 'TARGET_ALL_FOO_VALUE'
os.environ['TARGET_ALL_BAR'] = 'TARGET_ALL_BAR_VALUE'
print(TargetAllSettings().model_dump())
#> {'foo': 'TARGET_ALL_FOO_VALUE', 'bar': 'TARGET_ALL_BAR_VALUE'}


class TargetAliasSettings(FooBarSettings):
    model_config = SettingsConfigDict(
        env_prefix='TARGET_ALIAS_',
        env_prefix_target='alias',
    )


os.environ['TARGET_ALIAS_FooAlias'] = 'TARGET_ALIAS_FOO_VALUE'
os.environ['BAR'] = 'TARGET_ALL_BAR_VALUE'
print(TargetAliasSettings().model_dump())
#> {'foo': 'TARGET_ALIAS_FOO_VALUE', 'bar': 'TARGET_ALL_BAR_VALUE'}


class TargetVarSettings(FooBarSettings):
    model_config = SettingsConfigDict(
        env_prefix='TARGET_VAR_',
        env_prefix_target='variable',
    )


os.environ['FooAlias'] = 'TARGET_VAR_FOO_VALUE'  # (1)!
os.environ['TARGET_VAR_BAR'] = 'TARGET_VAR_BAR_VALUE'
print(TargetVarSettings().model_dump())
#> {'foo': 'TARGET_VAR_FOO_VALUE', 'bar': 'TARGET_VAR_BAR_VALUE'}
```

### Custom settings source example

Source: https://github.com/pydantic/pydantic-settings/blob/main/_autodocs/api-reference/source-base-classes.md

Example of a custom source that returns a hardcoded value for every field. The settings class uses settings_customise_sources to use this source along with init_settings. The output is 'hardcoded'.

```python
from typing import Any

from pydantic import FieldInfo

from pydantic_settings import BaseSettings, PydanticBaseSettingsSource

class FixedSource(PydanticBaseSettingsSource):
    def get_field_value(self, field: FieldInfo, field_name: str) -> tuple[Any, str, bool]:
        return 'hardcoded', field_name, False

    def __call__(self) -> dict[str, Any]:
        data: dict[str, Any] = {}
        for name, field in self.settings_cls.model_fields.items():
            value, key, is_complex = self.get_field_value(field, name)
            data[key] = self.prepare_field_value(name, field, value, is_complex)
        return data

class Settings(BaseSettings):
    token: str

    @classmethod
    def settings_customise_sources(cls, settings_cls, init_settings, env_settings,
                                   dotenv_settings, file_secret_settings):
        return FixedSource(settings_cls), init_settings

print(Settings().token)  # 'hardcoded'
```

import os

### Nested model default partial update example

Source: https://github.com/pydantic/pydantic-settings/blob/main/docs/index.md

Shows how to enable or disable partial updates on nested model default objects using the `nested_model_default_partial_update` flag. When enabled, the existing SubModel instance is updated; when disabled, a new instance is created. The example sets an environment variable and asserts the resulting model dump.

```python
import os

from pydantic import BaseModel

from pydantic_settings import BaseSettings, SettingsConfigDict


class SubModel(BaseModel):
    val: int = 0
    flag: bool = False


class SettingsPartialUpdate(BaseSettings):
    model_config = SettingsConfigDict(
        env_nested_delimiter='__', nested_model_default_partial_update=True
    )

    nested_model: SubModel = SubModel(val=1)


class SettingsNoPartialUpdate(BaseSettings):
    model_config = SettingsConfigDict(
        env_nested_delimiter='__', nested_model_default_partial_update=False
    )

    nested_model: SubModel = SubModel(val=1)


# Apply a partial update to the default object using environment variables
os.environ['NESTED_MODEL__FLAG'] = 'True'

# When partial update is enabled, the existing SubModel instance is updated
# with nested_model.flag=True change
assert SettingsPartialUpdate().model_dump() == {
    'nested_model': {'val': 1, 'flag': True}
}

# When partial update is disabled, a new SubModel instance is instantiated
# with nested_model.flag=True change
assert SettingsNoPartialUpdate().model_dump() == {
    'nested_model': {'val': 0, 'flag': True}
}
```

### CliApp.run_subcommand with nested subcommands

Source: https://github.com/pydantic/pydantic-settings/blob/main/docs/index.md

Demonstrates recursive subcommand execution using CliApp.run_subcommand. The Git model defines subcommands for 'init' and 'clone', each with their own cli_cmd method. The example runs the 'init' subcommand and asserts the resulting model dump. Note that subcommand models must define a cli_cmd method.

```python
from pydantic import BaseModel

from pydantic_settings import CliApp, CliPositionalArg, CliSubCommand


class Init(BaseModel):
    directory: CliPositionalArg[str]

    def cli_cmd(self) -> None:
        print(f'git init "{self.directory}"')
        #> git init "dir"
        self.directory = 'ran the git init cli cmd'


class Clone(BaseModel):
    repository: CliPositionalArg[str]
    directory: CliPositionalArg[str]

    def cli_cmd(self) -> None:
        print(f'git clone from "{self.repository}" into "{self.directory}"')
        self.directory = 'ran the clone cli cmd'


class Git(BaseModel):
    clone: CliSubCommand[Clone]
    init: CliSubCommand[Init]

    def cli_cmd(self) -> None:
        CliApp.run_subcommand(self)


cmd = CliApp.run(Git, cli_args=['init', 'dir'])
assert cmd.model_dump() == {
    'clone': None,
    'init': {'directory': 'ran the git init cli cmd'},
}
```

### Add custom JSON settings source with settings_customise_sources

Source: https://github.com/pydantic/pydantic-settings/blob/main/docs/index.md

Defines a custom `JsonConfigSettingsSource` that loads variables from a JSON file and adds it to the sources tuple. The custom source is placed between init and env sources, and the example prints `foobar='test'`.

```python
import json
from pathlib import Path
from typing import Any

from pydantic.fields import FieldInfo

from pydantic_settings import (
    BaseSettings,
    PydanticBaseSettingsSource,
    SettingsConfigDict,
)


class JsonConfigSettingsSource(PydanticBaseSettingsSource):
    """
    A simple settings source class that loads variables from a JSON file
    at the project's root.

    Here we happen to choose to use the `env_file_encoding` from Config
    when reading `config.json`
    """

    def get_field_value(
        self, field: FieldInfo, field_name: str
    ) -> tuple[Any, str, bool]:
        encoding = self.config.get('env_file_encoding')
        file_content_json = json.loads(
            Path('tests/example_test_config.json').read_text(encoding)
        )
        field_value = file_content_json.get(field_name)
        return field_value, field_name, False

    def prepare_field_value(
        self, field_name: str, field: FieldInfo, value: Any, value_is_complex: bool
    ) -> Any:
        return value

    def __call__(self) -> dict[str, Any]:
        d: dict[str, Any] = {}

        for field_name, field in self.settings_cls.model_fields.items():
            field_value, field_key, value_is_complex = self.get_field_value(
                field, field_name
            )
            field_value = self.prepare_field_value(
                field_name, field, field_value, value_is_complex
            )
            if field_value is not None:
                d[field_key] = field_value

        return d


class Settings(BaseSettings):
    model_config = SettingsConfigDict(env_file_encoding='utf-8')

    foobar: str

    @classmethod
    def settings_customise_sources(
        cls,
        settings_cls: type[BaseSettings],
        init_settings: PydanticBaseSettingsSource,
        env_settings: PydanticBaseSettingsSource,
        dotenv_settings: PydanticBaseSettingsSource,
        file_secret_settings: PydanticBaseSettingsSource,
    ) -> tuple[PydanticBaseSettingsSource, ...]:
        return (
            init_settings,
            JsonConfigSettingsSource(settings_cls),
            env_settings,
            file_secret_settings,
        )


print(Settings())
#> foobar='test'
```

### Custom EnvSettingsSource to parse environment variable values

Source: https://github.com/pydantic/pydantic-settings/blob/main/docs/index.md

Defines MyCustomSource that overrides prepare_field_value to parse comma-separated values for the 'numbers' field and JSON for others. The Settings class uses this source via settings_customise_sources. The example sets the environment variable and prints the parsed model.

### Reusable comma-separated parsing with NoDecode and BeforeValidator

Source: https://github.com/pydantic/pydantic-settings/blob/main/docs/index.md

Combines NoDecode with BeforeValidator in an annotated type to create a reusable CommaSeparated type for fields like cors_origins and trusted_hosts. The example sets environment variables and outputs a dict with lists of strings.

```python
import os
from typing import Annotated, Any

from pydantic import BeforeValidator

from pydantic_settings import BaseSettings, NoDecode


def split_comma(value: Any) -> Any:
    if isinstance(value, str):
        return [item.strip() for item in value.split(',')]
    return value


CommaSeparated = Annotated[list[str], NoDecode, BeforeValidator(split_comma)]


class Settings(BaseSettings):
    cors_origins: CommaSeparated = []
    trusted_hosts: CommaSeparated = []


os.environ['cors_origins'] = 'https://a.com, https://b.com'
os.environ['trusted_hosts'] = 'a.internal'
print(Settings().model_dump())
"""
{'cors_origins': ['https://a.com', 'https://b.com'], 'trusted_hosts': ['a.internal']}
"""
```

```APIDOC

    PydanticBaseSettingsSource,

    @classmethod
    def settings_customise_sources(
        cls,
        settings_cls: type[BaseSettings],
        init_settings: PydanticBaseSettingsSource,
        env_settings: PydanticBaseSettingsSource,
        dotenv_settings: PydanticBaseSettingsSource,
        file_secret_settings: PydanticBaseSettingsSource,

            GoogleSecretManagerSettingsSource(settings_cls, project_id='my-project'),
            init_settings,
            env_settings,
            dotenv_settings,
            file_secret_settings,
        )

### Reload settings in-place with __init__

Source: https://github.com/pydantic/pydantic-settings/blob/main/docs/index.md

Shows how to reload an existing settings instance by calling its `__init__` method. After setting an environment variable, the reload picks up the new value; after removing it, the reload restores the default.

```python
import os

from pydantic_settings import BaseSettings


class Settings(BaseSettings):

mutable_settings = Settings()

os.environ['foo'] = 'bar'
print(mutable_settings.foo)
#> foo

mutable_settings.__init__()
print(mutable_settings.foo)
#> bar

os.environ.pop('foo')
mutable_settings.__init__()
print(mutable_settings.foo)
#> foo
```

### Force JSON parsing per-field with ForceDecode

Source: https://github.com/pydantic/pydantic-settings/blob/main/docs/index.md

Annotate a field with ForceDecode to force JSON parsing even when enable_decoding=False. The example shows numbers (ForceDecode) parsed as JSON and numbers1 (without ForceDecode) parsed by a custom validator. Outputs {'numbers': [1, 2, 3], 'numbers1': [1, 2, 3]}.

```python
import os
from typing import Annotated

from pydantic import field_validator

from pydantic_settings import BaseSettings, ForceDecode, SettingsConfigDict


class Settings(BaseSettings):
    model_config = SettingsConfigDict(enable_decoding=False)

    numbers: Annotated[list[int], ForceDecode]
    numbers1: list[int]  # (1)!

    @field_validator('numbers1', mode='before')
    @classmethod
    def decode_numbers1(cls, v: str) -> list[int]:
        return [int(x) for x in v.split(',')]


os.environ['numbers'] = '["1","2","3"]'
os.environ['numbers1'] = '1,2,3'
print(Settings().model_dump())

### Inspect EnvSettingsSource with nested env var

Source: https://github.com/pydantic/pydantic-settings/blob/main/_autodocs/api-reference/env-and-dotenv-sources.md

Shows how to instantiate EnvSettingsSource directly to inspect resolved values from environment variables. Uses APP_SUB_MODEL__V2 to populate a nested SubModel, and demonstrates get_field_value and prepare_field_value methods. The environment variable is set and then popped after use.

```python
import os
from typing import Any

from pydantic import BaseModel
from pydantic.fields import FieldInfo

from pydantic_settings import BaseSettings, EnvSettingsSource, SettingsConfigDict

class SubModel(BaseModel):
    v2: str = 'default'

class Settings(BaseSettings):
    model_config = SettingsConfigDict(env_prefix='APP_', env_nested_delimiter='__')

    sub_model: SubModel

# APP_SUB_MODEL__V2=value -> {'sub_model': {'v2': 'value'}}
os.environ['APP_SUB_MODEL__V2'] = 'value'

# Instantiate the source directly and inspect its resolved values:
src = EnvSettingsSource(Settings)
print(src())
# {'sub_model': {'v2': 'value'}}

# get_field_value returns (value, key, value_is_complex) for a single field;
# no direct APP_SUB_MODEL var exists, so value is None and the field is marked complex:
field: FieldInfo = Settings.model_fields['sub_model']
print(src.get_field_value(field, 'sub_model'))  # (None, 'sub_model', True)
# prepare_field_value then explodes APP_SUB_MODEL__V2 into the nested dict:
print(src.prepare_field_value('sub_model', field, None, True))
# {'v2': 'value'}
os.environ.pop('APP_SUB_MODEL__V2')
```

### EnvSettingsSource

Source: https://github.com/pydantic/pydantic-settings/blob/main/_autodocs/api-reference/env-and-dotenv-sources.md

The EnvSettingsSource class reads settings from environment variables. It can be instantiated directly to inspect resolved values. Key methods include __call__ (returns a dict of all resolved values), get_field_value (returns the value, key, and complexity flag for a single field), and prepare_field_value (prepares a field value, e.g., exploding nested delimiters).

```APIDOC
## EnvSettingsSource

### Description
Reads settings from environment variables. Can be instantiated directly to inspect resolved values.

### Constructor
`EnvSettingsSource(settings_cls: type[BaseSettings], ...)`

### Methods

#### __call__
Returns a dictionary of all resolved settings values.

#### get_field_value(field, field_name)
Returns a tuple `(value, key, value_is_complex)` for a single field.

#### prepare_field_value(field_name, field, value, value_is_complex)
Prepares a field value, e.g., explodes nested delimiters into a nested dict.

### Example
```python
import os
from typing import Any

from pydantic import BaseModel
from pydantic.fields import FieldInfo

from pydantic_settings import BaseSettings, EnvSettingsSource, SettingsConfigDict

class SubModel(BaseModel):
    v2: str = 'default'

class Settings(BaseSettings):
    model_config = SettingsConfigDict(env_prefix='APP_', env_nested_delimiter='__')

    sub_model: SubModel

# APP_SUB_MODEL__V2=value -> {'sub_model': {'v2': 'value'}}
os.environ['APP_SUB_MODEL__V2'] = 'value'

# Instantiate the source directly and inspect its resolved values:
src = EnvSettingsSource(Settings)
print(src())
# {'sub_model': {'v2': 'value'}}

# get_field_value returns (value, key, value_is_complex) for a single field;
# no direct APP_SUB_MODEL var exists, so value is None and the field is marked complex:
field: FieldInfo = Settings.model_fields['sub_model']
print(src.get_field_value(field, 'sub_model'))  # (None, 'sub_model', True)
# prepare_field_value then explodes APP_SUB_MODEL__V2 into the nested dict:
print(src.prepare_field_value('sub_model', field, None, True))
# {'v2': 'value'}
os.environ.pop('APP_SUB_MODEL__V2')
```

### Basic CliSubCommand and CliPositionalArg usage with get_subcommand

Source: https://github.com/pydantic/pydantic-settings/blob/main/docs/index.md

Defines a Git settings model with clone and init subcommands, each using CliPositionalArg. Shows how to run without subcommands, handle missing subcommand errors with SettingsError, use is_required=False, and retrieve parsed subcommands with get_subcommand.

```python
import sys

from pydantic import BaseModel

from pydantic_settings import (
    BaseSettings,
    CliPositionalArg,
    CliSubCommand,
    SettingsError,
    get_subcommand,
)


class Init(BaseModel):
    directory: CliPositionalArg[str]


class Clone(BaseModel):
    repository: CliPositionalArg[str]
    directory: CliPositionalArg[str]


class Git(BaseSettings, cli_parse_args=True, cli_exit_on_error=False):
    clone: CliSubCommand[Clone]
    init: CliSubCommand[Init]


# Run without subcommands
sys.argv = ['example.py']
cmd = Git()
assert cmd.model_dump() == {'clone': None, 'init': None}

try:
    # Will raise an error since no subcommand was provided
    get_subcommand(cmd).model_dump()
except SettingsError as err:
    assert str(err) == 'Error: CLI subcommand is required {clone, init}'

# Will not raise an error since subcommand is not required
assert get_subcommand(cmd, is_required=False) is None


# Run the clone subcommand
sys.argv = ['example.py', 'clone', 'repo', 'dest']
cmd = Git()
assert cmd.model_dump() == {
    'clone': {'repository': 'repo', 'directory': 'dest'},
    'init': None,
}

# Returns the subcommand model instance (in this case, 'clone')
assert get_subcommand(cmd).model_dump() == {
    'directory': 'dest',
    'repository': 'repo',
}

    cli_show_env_vars: bool | None = None,
    cli_cmd_method_name: str = 'cli_cmd',
    **model_init_data: Any,
) -> T:
```

### Parameters
- **model_cls** (type[T]) - Required - `BaseSettings` subclass, `BaseModel` subclass, or pydantic `dataclass`. Anything else raises `SettingsError: Error: <name> is not subclass of BaseModel or pydantic.dataclasses.dataclass`.
- **cli_args** (list[str] | Namespace | SimpleNamespace | dict[str, Any] | None) - Optional - `None` → parse `sys.argv[1:]`. Namespace/dict inputs require `cli_settings_source` (else `SettingsError: Error: \`cli_args\` must be list[str] or None when \`cli_settings_source\` is not used`).
- **cli_settings_source** (CliSettingsSource[Any] | None) - Optional - User-defined CLI source; with namespace/dict args it is invoked as `cli_settings_source(parsed_args=...)`, else `cli_settings_source(args=...)`.
- **cli_exit_on_error** (bool | None) - Optional - For `BaseSettings` subclasses defaults to their config value; otherwise `True`.
- **cli_show_env_vars** (bool | None) - Optional - Show env var names in CLI help.
- **cli_cmd_method_name** (str) - Optional - The entrypoint method name to run. Defaults to `'cli_cmd'`.
- **model_init_data** (Any) - Optional - Extra model init kwargs.

### Returns
- **T** - The ran model instance (the `cli_cmd` may mutate it, e.g. `self.this_foo = ...`).

### Behavior
- For non-`BaseSettings` models, an internal `CliAppBaseSettings` subclass is created with `nested_model_default_partial_update=True`, `case_sensitive=True`, `cli_hide_none_type=True`, `cli_avoid_json=True`, `cli_enforce_required=True`, `cli_implicit_flags=True`, `cli_kebab_case=True`, carrying over the dataclass's `populate_by_name`/`validate_by_alias`/`validate_by_name` config.
- Async commands: when `cli_cmd` is a coroutine function (`inspect.iscoroutinefunction`), it is executed with `asyncio.run()` — unless an event loop is already running in the thread (e.g. Jupyter), in which case it runs in a separate thread and exceptions are re-raised in the caller.

### Example
```python
from pydantic_settings import BaseSettings, CliApp

class Settings(BaseSettings):
    this_foo: str

    def cli_cmd(self) -> None:
        print(f'hello {self.this_foo}')
        self.this_foo = 'mutated'

s = CliApp.run(Settings, cli_args=['--this_foo', 'bar'])
assert s.this_foo == 'mutated'
```

### CliSubCommand and CliPositionalArg usage

Source: https://github.com/pydantic/pydantic-settings/blob/main/docs/index.md

Demonstrates defining CLI subcommands and positional arguments with CliSubCommand and CliPositionalArg, including retrieving the parsed subcommand with get_subcommand.

```APIDOC
## CliSubCommand and CliPositionalArg usage

### Description
Defines a CLI settings model with subcommands and positional arguments using CliSubCommand and CliPositionalArg annotations. Shows how to parse subcommands and retrieve them with get_subcommand.

### Usage
- Define a BaseModel for each subcommand, with fields annotated as CliPositionalArg for positional arguments.
- In the BaseSettings model, add fields annotated as CliSubCommand for each subcommand.
- Use get_subcommand(model) to retrieve the parsed subcommand instance.

### Parameters
- `CliSubCommand` - Annotation for a subcommand field. Must be applied to required fields (no default). The type must be a pydantic BaseModel or pydantic.dataclasses dataclass.
- `CliPositionalArg` - Annotation for a positional argument field.
- `get_subcommand(model, is_required=True)` - Utility function to retrieve the parsed subcommand. Set `is_required=False` to avoid raising an error if no subcommand is found.

### Example
```py
import sys
from pydantic import BaseModel
from pydantic_settings import BaseSettings, CliPositionalArg, CliSubCommand, SettingsError, get_subcommand

class Init(BaseModel):
    directory: CliPositionalArg[str]

class Clone(BaseModel):
    repository: CliPositionalArg[str]
    directory: CliPositionalArg[str]

class Git(BaseSettings, cli_parse_args=True, cli_exit_on_error=False):
    clone: CliSubCommand[Clone]
    init: CliSubCommand[Init]

# Run without subcommands
sys.argv = ['example.py']
cmd = Git()
assert cmd.model_dump() == {'clone': None, 'init': None}

try:
    get_subcommand(cmd).model_dump()
except SettingsError as err:
    assert str(err) == 'Error: CLI subcommand is required {clone, init}'

assert get_subcommand(cmd, is_required=False) is None

# Run the clone subcommand
sys.argv = ['example.py', 'clone', 'repo', 'dest']
cmd = Git()
assert cmd.model_dump() == {'clone': {'repository': 'repo', 'directory': 'dest'}, 'init': None}
assert get_subcommand(cmd).model_dump() == {'directory': 'dest', 'repository': 'repo'}
```

class Git(BaseSettings):

    def cli_cmd(self) -> None:
        # Run the final subcommand (clone/init). It is recommended to define async methods only at the deepest level.

@overload
def __call__(self, *, args: list[str] | tuple[str, ...] | bool) -> CliSettingsSource[T]: ...

@overload
def __call__(self, *, parsed_args: Namespace | SimpleNamespace | dict[str, Any]) -> CliSettingsSource[T]: ...

def __call__(
    self,
    *,
    args: list[str] | tuple[str, ...] | bool | None = None,
    parsed_args: Namespace | SimpleNamespace | dict[str, list[str] | str] | None = None,
) -> dict[str, Any] | CliSettingsSource[T]:
```

### Parameters
#### Keyword Arguments
- **args** (list[str] | tuple[str, ...] | bool | None) - Optional - If `True`, parse `sys.argv[1:]`; if `False`, re-load with no args (unknowns cleared); if a list or tuple, parse that argument list and load the result.
- **parsed_args** (Namespace | SimpleNamespace | dict[str, Any] | None) - Optional - Load pre-parsed arguments (e.g. from an external parser).

### Behavior
- No arguments: behaves as a settings source — returns the values dict (`dict[str, Any]`), parsing nothing new.
- `args=True`: parse `sys.argv[1:]`; `args=False`: re-load with no args (unknowns cleared); `args=<list|tuple>`: parse that argument list and load the result. Returns `self`.
- `parsed_args=Namespace | SimpleNamespace | dict`: load pre-parsed arguments (e.g. from an external parser). Returns `self`.
- Passing both `args` and `parsed_args` raises `SettingsError: \`args\` and \`parsed_args\` are mutually exclusive`.

### Parsing Behavior
Parsed option values are normalized: repeated options merge (argparse-style `--tag a --tag b` → `['a','b']`), lazy `1,2,3` and JSON `'[1,2]'` forms are accepted; dict fields accept `k=v` repeats and JSON; literal/enum choices are validated. Unknown arguments are errors (`SystemExit(2)`) unless `cli_ignore_unknown_args` or a `CliUnknownArgs` field captures them.

### Returns
- `dict[str, Any]` - When called with no arguments.
- `CliSettingsSource[T]` - When called with `args` or `parsed_args`.
```

### DotEnvSettingsSource

Source: https://github.com/pydantic/pydantic-settings/blob/main/_autodocs/api-reference/env-and-dotenv-sources.md

The DotEnvSettingsSource class reads settings from dotenv files via python-dotenv. It is a subclass of EnvSettingsSource and accepts parameters for file paths, encoding, filtering, and more. It also provides a static helper to read a single dotenv file.

```APIDOC
## DotEnvSettingsSource

### Description
Reads settings from dotenv files via python-dotenv. Subclass of EnvSettingsSource. Env variables still take priority over dotenv values.

### Constructor
`DotEnvSettingsSource(settings_cls, env_file=ENV_FILE_SENTINEL, env_file_encoding=None, dotenv_filtering=None, case_sensitive=None, env_prefix=None, env_prefix_target=None, env_nested_delimiter=None, env_nested_max_split=None, env_ignore_empty=None, env_parse_none_str=None, env_parse_enums=None, env_file_depth=None, _init_state=None)`

### Parameters
- `env_file` (DotenvType | None) - Default: ENV_FILE_SENTINEL - File(s) to read; None disables. Multiple files load in order, later files overriding earlier ones. Relative paths are resolved with env_file_depth parent-directory search; FIFOs are accepted.

- `dotenv_filtering` (DotenvFiltering | None) - Default: None - See below.
- `env_file_depth` (int | None) - Default: None - Levels up from cwd to search for the env file.
- Remaining parameters mirror EnvSettingsSource.

### Reload settings by swapping cached reference in a worker thread

Source: https://github.com/pydantic/pydantic-settings/blob/main/docs/index.md

Use this snippet to reload cached settings in an async application. It constructs a fresh Settings instance in a worker thread and rebinds the global cached_settings reference. Rebinding is atomic, so concurrent readers always see a fully-initialized object. The output prints the api_key value 'secret'.

```python
import asyncio
from pathlib import Path

from pydantic_settings import BaseSettings, SettingsConfigDict

env_path = Path('example.env')
env_path.write_text('api_key=secret\n', encoding='utf-8')


class Settings(BaseSettings):
    api_key: str

    model_config = SettingsConfigDict(env_file=env_path)


cached_settings = Settings()


async def reload_settings() -> None:
    global cached_settings
    cached_settings = await asyncio.to_thread(Settings)


asyncio.run(reload_settings())
print(cached_settings.api_key)
#> secret

env_path.unlink(missing_ok=True)
```

### SecretsSettingsSource.get_field_value

Source: https://github.com/pydantic/pydantic-settings/blob/main/_autodocs/api-reference/secrets-sources.md

Retrieves the value for a given field by searching the secrets directories in reverse order. The first existing file is read and stripped of whitespace.

```APIDOC
## SecretsSettingsSource.get_field_value

### Description
For each candidate `(field_key, env_name, value_is_complex)`, searches the secrets directories in reverse order (last-wins) via `find_case_path`. The first existing file is read as UTF-8 and stripped of whitespace. If a path exists but is not a file, a `UserWarning` is issued. Missing files are skipped silently.

### Nested model unknown key raises ValidationError with extra='forbid'

Source: https://github.com/pydantic/pydantic-settings/blob/main/docs/index.md

Demonstrates that an incorrect env_nested_delimiter (single underscore) keeps the variable from matching, but a correct delimiter (double underscore) passes the unknown key to the nested model, causing a ValidationError with type 'extra_forbidden'.

```python

    database: Database = Database()

print(Settings().database.port)
#> 5432
del os.environ['APP_DATABASE_PORT']

# The nested prefix matches, so the unknown key reaches Database's validation.
os.environ['APP_DATABASE__PRT'] = '6543'
try:

except ValidationError as exc:

    #> extra_forbidden

### NoDecode / ForceDecode

Source: https://github.com/pydantic/pydantic-settings/blob/main/_autodocs/types.md

Marker annotations that control JSON decoding of complex field values. NoDecode prevents decoding, while ForceDecode forces decoding even when disabled by configuration.

```APIDOC
## NoDecode / ForceDecode

### Description
Marker annotations that control JSON decoding of complex field values. `NoDecode` prevents decoding, while `ForceDecode` forces decoding even when disabled by configuration.

### Source
`pydantic_settings/sources/types.py` (lines 23 and 27)

### Class Definitions
```python
class NoDecode:
    """Annotation to prevent decoding of a field value."""

class ForceDecode:
    """Annotation to force decoding of a field value."""
```

### Behavior
- `NoDecode` in field metadata (or `enable_decoding=False` without `ForceDecode`) skips `json.loads` in `PydanticBaseSettingsSource.decode_complex_value`; the raw string is passed to validation (pair with a `BeforeValidator` to parse).

    return [x.strip() for x in v.split(',')] if isinstance(v, str) else v

class Settings(BaseSettings):
    tags: Annotated[list[str], NoDecode, BeforeValidator(split_csv)]
    strict: Annotated[list[int], ForceDecode]  # decoded even with enable_decoding=False
