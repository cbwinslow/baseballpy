### GET /api/v1/standings

Source: https://raw.githubusercontent.com/saiemgilani/sdv-swagger/main/mlb-stats-api.openapi.yaml

API endpoint for GET /api/v1/standings

```markdown
### Parameters

- **leagueId** (string, query, required)
- **season** (string, query, optional)
- **date** (string (date), query, optional)
- **standingsTypes** (string, query, optional)
- **hydrate** (string, query, optional): Comma-separated list of related resources to expand. Supports nesting via
parentheses, e.g. `team(roster(person(stats(splits))))`.
Common values: probablePitcher, linescore, team, person, stats, decisions,
flags, broadcasts, content, weather.

- **fields** (string, query, optional): Comma-separated allow-list of JSON keys to keep. Hierarchical:
`teams,id,name` returns only `teams[].id` and `teams[].name`. Significant
bandwidth savings on large responses.


### Responses

#### 200 - response


### Example Usage

```bash
curl -X GET "https://statsapi.mlb.com/api/v1/standings?leagueId=string&season=string&date=2023-01-01&standingsTypes=string&hydrate=string&fields=string"
```

Returns games for a date, date range, team, or season. The response is
nested as `dates[].games[]`. Use `hydrate=probablePitcher,linescore,team`
for the most common enrichments.


```markdown

- **startDate** (string (date), query, optional)
- **endDate** (string (date), query, optional)
- **teamId** (integer, query, optional)
- **opponentId** (integer, query, optional)
- **season** (string, query, optional)
- **gameType** (string, query, optional)
- **gamePk** (integer, query, optional)
- **hydrate** (string, query, optional): Comma-separated list of related resources to expand. Supports nesting via
parentheses, e.g. `team(roster(person(stats(splits))))`.
Common values: probablePitcher, linescore, team, person, stats, decisions,
flags, broadcasts, content, weather.

- **fields** (string, query, optional): Comma-separated allow-list of JSON keys to keep. Hierarchical:
`teams,id,name` returns only `teams[].id` and `teams[].name`. Significant
bandwidth savings on large responses.


### Responses

#### 200 - response


### Example Usage

```bash
curl -X GET "https://statsapi.mlb.com/api/v1/schedule?sportId=1&date=2023-01-01&startDate=2023-01-01&endDate=2023-01-01&teamId=0&opponentId=0&season=string&gameType=string&gamePk=0&hydrate=string&fields=string"

### GET /api/v1.1/game/{gamePk}/feed/live

Source: https://raw.githubusercontent.com/saiemgilani/sdv-swagger/main/mlb-stats-api.openapi.yaml

Full event-by-event feed for a game, including play results, baserunners,
pitch data, and Statcast-flavored hit data where available. Updates in
near-real-time during a live game. Note this is the only commonly-used
v1.1 endpoint.


```markdown
### Parameters

- **gamePk** (integer, path, required): MLB's internal game ID, found in schedule responses.
- **timecode** (string, query, optional): ISO-ish timestamp `YYYYMMDD_HHMMSS`. If set, returns the state of the
game at that point. Used for replay / scrubbing.


### Responses

#### 200 - response


### Example Usage

```bash
curl -X GET "https://statsapi.mlb.com/api/v1.1/game/{gamePk}/feed/live?timecode=string"
```

### API Overview: MLB Stats API (unofficial)

Source: https://raw.githubusercontent.com/saiemgilani/sdv-swagger/main/mlb-stats-api.openapi.yaml

The MLB Stats API powers MLB.com, the At Bat app, and most public baseball stat
sites. It is not officially documented for public use; this spec is consolidated
from the toddrob99/MLB-StatsAPI Python wrapper, the pseudo-r/Public-MLB-API
project, and MLB's own 2025 hackathon dataset.

Coverage: the endpoints below are the ones we plan to wrap. The full surface
area is larger (~150 endpoints); see toddrob99/MLB-StatsAPI/statsapi/endpoints.py
for the full enumeration.

Common conventions:
  - `sportId=1` selects MLB. Most endpoints default to MLB but require the param
    explicitly for some queries.
  - `season` is a 4-digit year string.
  - `fields` is a comma-separated allow-list of JSON keys to return.
  - `hydrate` is a comma-separated list of related resources to expand inline.
    Hydrations can be nested with parentheses, e.g. `team(roster(person))`.
  - All responses are JSON unless noted. No authentication required.
