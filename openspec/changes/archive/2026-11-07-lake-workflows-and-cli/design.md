# Design

- **Fast status:** each processed dataset keeps `_manifest.json` with `records_count`, `season` and `completed_at` per finished chunk; chunks stay in the manifest after compaction, so the sum equals the rows on disk. Evidence: `catalog status --source statcast --source lahman` took 9.5 s end to end; `status` for all 480 datasets took 17.6 s while a download was running (the full footer scan did not finish in 110 s). `--verify` keeps the old scan and `test_verify_counts_the_files_and_catches_a_manifest_that_is_wrong` shows the two can disagree and which one is the check. Looking must not create folders (the manifest tracker makes its parent folder), so the scan tests for the file first.
- **Running downloads:** every download process holds an operating-system lock per host (`core/hostlock.py`); `busy_hosts` tries each lock and drops it at once, so `status` can say which hosts are being downloaded from without a process list.
- **Plans:** TOML packaged in `baseballpy/ingest/plans/`; `current` resolves at plan time so the plan never goes stale. No source name is hard-coded in code, only in the data file. The `daily` plan is `markets` (Kalshi, Polymarket), this season of Statcast and this season of the MLB API (dry run: 8 jobs). The `full` plan is the order of `docs/BACKFILL.md` (dry run: 253 jobs, estimated 36 GB).
- **Quarantine noise:** real records from the lake: a blank Retrosheet `position` cell and an MLB `leverage_index` of `NaN`. Both are legitimate values, not errors: blank is missing, `NaN` is a float. Truly wrong values (`"abc"` for an integer) are still quarantined (test).
- **Existing practice:** pandas and Arrow CSV readers treat empty fields as null and accept `NaN`/`inf` for floats by default; the change follows that.
